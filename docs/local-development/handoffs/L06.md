## Changed behavior

- Root commands (`package.json`, `scripts/local/workflow.mjs`):
  - `vp run local:setup` — generate configuration (idempotent), start, migrate, and
    health-check this worktree's PostgreSQL.
  - `vp run local:up` — start and health-check an already configured database.
  - `vp run dev` — unchanged; starts the web app with the sealed local runtime profile.
  - `vp run test:integration` — setup, start, migrate, then run `db:rehearse`,
    `test:core-storage`, `test:auth-browser`, `test:offline-analysis`, and
    `evaluate:core:fixture`. Stops the local container afterward only if this command
    started it; the volume is never deleted.
  - `vp run local:reset` — delegates to the existing target-verified `db:local:reset`.
  - `vp run local:down` — stops the container without deleting data.
- CI (`.github/workflows/local-development.yml`): runs on pull requests and pushes to
  `main` with `contents: read` and no repository secrets. It installs dependencies, pulls
  the digest-pinned pgvector image and Chromium, generates synthetic configuration, runs
  `vp check`, `vp run check-types`, and `vp run build`, then runs `vp test --run` and
  `vp run test:integration` under `scripts/ci/with-network-denied.sh`.
- `scripts/ci/with-network-denied.sh` refuses to run outside Linux CI, installs
  iptables/ip6tables `OUTPUT` rules that allow only loopback and the Docker bridge
  subnet, and removes the rules on exit.
- Documentation: new `docs/local-development/README.md` (prerequisites, workflow, ports,
  roles, fixtures, reset safety, CI boundary, separately authorized live work);
  `docs/environment.md` links to it; `PLAN.md` status updated.
