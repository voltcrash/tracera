## Changed behavior

- **Explicit profiles and roles.** New `@repo/environment` package (`packages/environment/src/index.js`) validates `TRACERA_PROFILE` (`local`, `test`, `deployed`) and `TRACERA_CONFIG_ROLE` (`runtime`, `migration`, `test-provisioning`, `analysis`). Profiles are never inferred from `NODE_ENV`; `vp run build` is a production-mode Next build that still selects the local profile.
- **Role separation.** Each role receives only its own database URL. The runtime role rejects `DATABASE_MIGRATOR_URL` and `TEST_DATABASE_PROVISIONER_URL`; migration and analysis roles reject runtime-only auth and safeguard settings; `test-provisioning` is refused with the deployed profile. `CORE_STORAGE_TEST_DATABASE_URL` is accepted only by `test`/`runtime`.
- **Generated worktree configuration.** `vp run env:setup` (`scripts/environment/setup.mjs`) derives a worktree ID and port (20000–39999) from the worktree's real path. It writes random passwords and a Better Auth secret to mode-0600 files under ignored `.tracera/environment/{local,test}/`. Existing files are never rotated or overwritten, and legacy environment files are never read.
- **Precedence.** `scripts/environment/run.mjs` reads exactly `shared.env` and then `<role>.env`. Duplicate keys, unknown keys, and launcher-controlled keys in those files are errors. Before loading, it rejects inherited managed or profile variables from the shell, plus any `.env`/`.env.*` file (other than `.env.example`) in the root, `apps/web`, or `packages/{ai,auth,db}`. The selected values are sealed with a SHA-256 digest, so later injection (for example, Next.js loading an app `.env` file) fails validation.
- **Validation before connections.** Checks run in `next.config.js`, the request proxy, `packages/db` at import time and in `configureDatabase`, `drizzle.config.ts`, and `scripts/environment/guard.mjs`, which wraps `db:generate`, `db:migrate`, and all `@repo/ai` scripts. The Core storage integration test also validates its target before creating a pool. Local/test targets must be loopback, match the generated host/port/database name, and use the role's expected username. Local/test profiles reject OAuth credentials, AI keys and base URLs, and Fact Check, NewsAPI, and Jina keys.
- **Redacted diagnostics.** `vp run env:diagnose:local` prints only the profile, role, username, host, port, and database name.
- **Documentation.** `docs/environment.md` covers profiles, precedence, deployed role examples (`config/environment/deployed.*.env.example`), the deployment prerequisite, and the root `.env` retirement guide. Existing OAuth, GitHub App, dev-login, provider, safeguard, and RLS reference material is retained. The root `.env.example` now only points to the new workflow. `docs/local-development/PLAN.md` records L01–L06.

New root scripts: `env:setup`, `env:diagnose:local`, `db:migrate:local`, `evaluate:core:fixture`. `dev` and `build` now run through the local-profile launcher. `dev` and `db:migrate:local` require a reachable local PostgreSQL target.

## Configuration and migration instructions

- Local: `vp run env:setup`, then `vp run env:diagnose:local`. Do not create root or app `.env` files.
- Existing root `.env`: follow "Retiring a shared root `.env`" in `docs/environment.md`. Move it outside the repository without printing, sourcing, or copying it, and rotate credentials through their providers.
- **Deployment prerequisite (operator action before deploying this PR):** the hosted web environment must set `TRACERA_PROFILE=deployed` and `TRACERA_CONFIG_ROLE=runtime` for both build and runtime. It must not contain `DATABASE_MIGRATOR_URL`, `TEST_DATABASE_PROVISIONER_URL`, or `CORE_STORAGE_TEST_DATABASE_URL`. Without this, `next build` fails closed. The operator migration environment uses `TRACERA_PROFILE=deployed`, `TRACERA_CONFIG_ROLE=migration`, and only `DATABASE_MIGRATOR_URL`. L01 made no deployment configuration changes.
- No database migrations were added or run.

## Limitations

- No PostgreSQL is provisioned. `vp run dev` and `vp run db:migrate:local` fail by design until L02.
- Generated roles `tracera_migrator` and `tracera_test_provisioner` do not exist anywhere yet. L02 must create them with the generated passwords, or read the generated files to bootstrap.
- Worktree ports come from a hash and may collide. L02 should detect an occupied port that belongs to another worktree.
- The seal detects accidental modification, not a malicious local process, which could recompute it.
- Local sign-in without OAuth (L04) and offline analysis fixtures (L05) are not implemented. Local profiles reject provider credentials but add no fixture provider.
- Human-gold annotation, paid evaluation, calibration, and release approval remain separate, unsatisfied Core gates.
