## Behavior/API examples

The pure selector is available as:

```ts
const result = selectTopClaims({
  claims: completeInventoryClaims,
  snapshots: submittedSnapshots,
  coverage: completeCoverageAudit,
  inventoryStatus: "complete",
  primarySnapshotId: submittedSnapshots[0].id,
});
```

`result.claims` is the complete inventory. `result.selectedClaims` contains zero to three
canonical claims, and `result.selection.selectedClaimIds` preserves their rank order. Every
other canonical factual claim is returned in `result.claims` with `coverageDisposition: "deferred"`
and a corresponding selection entry/reason; duplicates, opinions, background, ambiguous,
unanswerable, non-checkable, uncertain-OCR, and extraction-deferred entries remain explicit.

Relevant fields from a focused artifact are:

```json
{
  "policyVersion": "core-v2-focused-1.0.0",
  "selectionVersion": "core-v2-focused-selection-1.0.0",
  "maxSelectedClaims": 3,
  "inventory": {
    "totalClaims": 5,
    "canonicalClaims": 5,
    "duplicateClaims": 0,
    "canonicalFactualClaims": 5,
    "eligibleClaims": 5,
    "analyzedClaims": 3,
    "deferredClaims": 2,
    "excludedClaims": 0
  },
  "selectedClaimIds": ["claim_headline", "claim_lead", "claim_body"],
  "deferredClaimIds": ["claim_four", "claim_five"]
}
```

The ranking is deterministic: eligible material/checkable factual claims are ordered by proven
headline, heading, lead, or body position, then concrete entity/date/place/quantity/measurable
event signals, then submitted document order, span start, and claim ID. No model confidence is
used. Retrieval, assessment, provenance, adjudication, calibration, and scoring receive only
`selectedClaims`; full `inputCoverage` and all inventory claims remain on the saved report.
The existing verdict semantics and score formula were not changed or supplemented with a new
score.

## Limitations and successor instructions

- Selection is an engineering policy with deterministic fixture coverage, not statistical
  calibration or a population-level accuracy claim. The focused product must not be described as
  statistically calibrated or universally accurate.
- The inventory is complete within the existing normalization/extraction limits. Partial,
  unavailable, unsupported, truncated, uncertain, and omitted input remains explicit; this task
  does not infer claims for text that was not retained or successfully extracted.
- The existing v2 calibration stage is still present for backward-compatible orchestration, but it
  receives selected claims only and the focused default has no fabricated calibrator artifact.
  A successor may add the focused no-calibration decision boundary described by
  `FOCUSED-PLAN.md`; it must not alter saved full-release report meaning.
- Keep `inputCoverage` and every `focusedSelection.claims` entry when adding evidence or API
  behavior. Only `focusedSelection.selectedClaimIds` may enter evidence-bearing stages. Do not
  turn deferred claims into unverified selected decisions, hide omitted work, or use model
  confidence as a ranking signal.
- Continue preserving immutable snapshots, exact offsets/quotes, source applicability and
  independence, safe-fetch/SSRF and prompt-injection controls, owner/tenant/visibility rules,
  quotas, cancellation, explicit unknown/unavailable states, and legacy v1 rendering.
- Do not invent calibration artifacts, probabilities, human labels, provider measurements, source
  history, or deployment evidence.

The successor should start from this branch's pushed tip, read `FOCUSED-PLAN.md`, and implement
the next focused evidence/verdict boundary on top of the selected-only seam.
