## Contract summary

Versions: `CORE_V2_SCHEMA_VERSION = 2`, `CORE_V2_CONTRACT_VERSION = "2.0.0"`,
`CORE_V2_SCORE_FORMULA_VERSION = "factual-supported-share-1.0.0"`,
`CORE_V2_RESOLUTION_COVERAGE_THRESHOLD = 0.8`, `CORE_V2_ENGINE_VERSION = "core-v2.0.0"`.

Import as:

```ts
import { runReportSchema, type RunReport } from "@repo/contracts/core-v2";
import type { RunEnvironment, RunAnalysisV2 } from "@repo/ai/src/core/types";
```

Stage signatures, all returning `{status, data, issues, metrics}`:

```ts
type RetrieveEvidenceV2 = (
  i: RetrieveEvidenceV2Input,
  env: RunEnvironment,
) => Promise<StageResult<RetrieveEvidenceV2Data>>;
type ScoreReportV2 = (i: ScoreReportV2Input) => StageResult<ScoreReportV2Data>;
type RunAnalysisV2 = (i: RunAnalysisV2Input, env: RunEnvironment) => Promise<RunAnalysisV2Result>;
```

`scoreReportV2` is the single synchronous pure stage. It takes no ports and receives the
orchestrator's clock reading as `input.at`, so a score is replayable from persisted
artifacts. The other eight stages take `RunEnvironment`, which carries `RunContext`, the
ports and the `AbortSignal`. Core logic reaches the database, the network, the model, the
clock and the audit sink only through those ports, so a fixture run needs no network,
no provider credentials and no production database.

A published decision is separated from a diagnostic one. `diagnosticLabel` is the
adjudicated label kept for evaluation and calibration; `publishedLabel` is what a user
sees. A decisive published label is structurally impossible without in-scope calibration,
a resolved challenge and valid citations:

```json
{
  "claimId": "claim_complete_1",
  "diagnosticLabel": "supported",
  "publishedLabel": "supported",
  "reasonCodes": ["supported_by_admissible_evidence"],
  "supportingAssessmentIds": ["assess_complete_1"],
  "challenge": { "status": "resolved", "agreed": true, "targetedRoundsUsed": 0 },
  "calibration": {
    "applicability": "in_scope",
    "calibratedCorrectness": 0.94,
    "calibratorVersion": "example-calibrator-0",
    "sliceId": "en/business/2026"
  },
  "rawModelConfidence": 0.88,
  "citationIntegrity": "valid"
}
```

`example-calibrator-0` is a placeholder that demonstrates the in-scope branch. No
calibrator has been fitted. Every other calibration branch carries a structural
`calibratedCorrectness: null`.

The full invariant list is in `docs/core-overhaul/contract-manifest.md`. The two that the
task's pass condition names directly:

- Excerpt offsets must reproduce the quoted text, every claim, snapshot and assessment
  reference must resolve inside the same report, and a decision may cite only validated
  assessments belonging to its own claim.
- `factualScore` is non-null exactly when `nullReasons` is empty and must then equal
  `100 * supported / (supported + contradicted)`. Zero eligible claims, zero resolved
  claims, partial input, partial extraction, coverage below `0.8` and an open material
  mixed or misleading claim each force their null reason. A canceled run carries no
  scorecard.

Every core entity is a `strictObject`. There is no `z.any`, `z.unknown` or open record in
any core evidence object; the only loose schema is `legacyRunReportSchema`, which exists
so saved v1 reports keep decoding.
