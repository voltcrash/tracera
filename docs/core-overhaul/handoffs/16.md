## Changed files and behavior

- `packages/contracts/src/core-v2.ts` adds focused selected/resolved score counts, explicit
  citation/conflict null reasons, focused count and coverage invariants, and report-integrity
  checks preventing decisions outside the selected claim set. Existing full-release and saved v1
  decoding remain supported.
- `packages/ai/src/core/scoring/score-report.ts`, `scoring/index.ts`, and `core/index.ts`
  implement and export `scoreFocusedReportV2`. Its formula is exactly
  `100 * supported / (supported + contradicted)` over deduplicated selected factual claims. It
  returns selected, resolved, verdict, deferred, omitted, coverage, evidence, origin, and
  presentation fields. The score is null for zero resolutions, focused coverage below `0.8`,
  partial input/extraction, material open mixed or misleading results, citation validation
  failure, or unresolved conflict. Unverified and misleading claims never count as resolutions.
  Exact snapshot quote/offset checks, cited-assessment checks, and applicability checks gate
  decisive focused labels.
- `packages/ai/src/core/selection/select-top-claims.ts` keeps the focused denominator tied to
  the selected IDs, deduplicates the selected factual scope, and reports deferred/omitted work
  without treating it as an unverified verdict or a score contribution.
- `packages/ai/src/core/run-analysis.ts`, `core/types.ts`, and `core/worker.ts` pass the focused
  selection, immutable snapshots, and exact tenant/owner/visibility scope through scoring and
  reuse. Replay uses the same focused score boundary.
- `packages/ai/src/core/reuse-policy.ts` requires exact content, proposition scope, focused
  policy/version, evidence hash, ownership/tenant/visibility, and freshness before reuse. Related
  stories and similar images remain context only.
- `packages/ai/src/core/report-view.ts` and new `packages/ai/src/core/timeline.ts` project
  separate source context, presentation findings, scoped provenance, OCR observations, and an
  immutable-snapshot timeline. Unknown or unavailable chronology/provenance remains unresolved;
  timeline entries never invent event dates. OCR exposes transcribed text and uncertainty while
  visual authenticity remains `not_verified`.
- `packages/ai/src/core/provenance/chronology.ts`, `pipeline/ground-zero.ts`, and the legacy
  trace/web copy use “earliest observed within the searched scope,” not a global-original claim.
  `packages/ai/src/core/ingestion/acquisition.ts` makes missing EXIF/C2PA or reverse-image
  results explicit and does not infer fabrication.
- `apps/web/src/components/analysis/core-v2-report.tsx` renders the focused score counts,
  null reasons, deferred and excluded claims, source/provider context, presentation-only
  observations, unresolved provenance/timeline entries, and OCR/authenticity limits. The legacy
  `trace-report.tsx` wording is scoped without changing saved v1 rendering behavior.
- `packages/ai/src/core/fixtures/focused-invariants.json`,
  `packages/ai/scripts/support/focused-scenarios.ts`,
  `packages/ai/scripts/evaluate-core-focused.ts`, `packages/ai/test/core-focused.test.ts`, and

## Behavior/API examples

The canonical focused scorer is available from `@repo/ai/core`:

```ts
const result = scoreFocusedReportV2({
  claims,
  decisions,
  assessments,
  snapshots,
  focusedSelection,
});
```

For three selected claims with two supported and one contradicted, all with valid decisive
publication and citations, the scorecard contains:

```json
{
  "formulaVersion": "focused-supported-share-1.0.0",
  "selectedClaimCount": 3,
  "resolvedClaimCount": 3,
  "counts": {
    "supported": 2,
    "contradicted": 1,
    "mixed": 0,
    "misleading": 0,
    "unverified": 0,
    "eligibleFactualClaims": 3,
    "deferredClaims": 0,
    "omittedClaims": 0
  },
  "resolutionCoverage": 1,
  "factualScore": 66.66666666666667,
  "nullReasons": []
}
```

Two supported claims and one unverified selected claim produce `resolvedClaimCount: 2`,
`unverified: 1`, `resolutionCoverage: 0.6666666666666666`, and a null factual score with
`resolution_coverage_below_threshold`; the unverified claim is not mapped to 50% and cannot
silently improve the score. Omitted selected work is counted separately and also keeps coverage
and null reasons explicit.

The report view keeps auxiliary signals separate:

```json
{
  "sourceContext": [{ "providerRating": "context-only" }],
  "presentationFindings": [{ "evidenceBacked": false }],
  "visualVerification": {
    "ocr": "uncertain",
    "visualProvenance": "not_verified"
  },
  "timeline": {
    "notice": "Timeline entries are immutable timestamp observations from stored snapshots; unknown times remain unresolved."
  }
}
```

Ground Zero and provenance use the searched-scope wording. Related/syndicated material, source
reputation, recency, origin, framing, OCR, and image metadata are context or separate fields and
do not enter factual accuracy.

## Limitations and successor instructions

- The focused evaluator and fixtures are deterministic engineering regression guardrails only.
  They are not a statistical release program, calibration evidence, or proof of population-level
  accuracy. Do not describe the focused product as statistically calibrated or universally
  accurate.
- Preserve the exact focused score formula, selected/resolved counts, `0.8` coverage threshold,
  explicit null reasons, immutable snapshots, exact quotes/offsets, applicability and
  independence checks, and selected-claim-only scoring when extending the API.
- Keep source reputation, framing, recency, origin, OCR, image authenticity, related context,
  and timeline observations separate from factual score. Missing metadata or unavailable
  provenance must remain unknown/unresolved rather than becoming fabrication or originality
  claims.
- Reuse must continue to validate exact content/scope/version/owner/tenant/visibility/evidence
  identity and freshness. Timeline entries must continue to derive only from stored immutable
  observations.
- Continue preserving authentication, safe fetch and SSRF protections, prompt-injection
  resistance, quotas, spend limits, cancellation, explicit partial/unavailable states, and
  backward-compatible v1 rendering. Run the Vite+ validation commands before the next stack
  change.
