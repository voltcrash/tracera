## Changed files and behavior

Owned path `packages/ai/src/core/provenance/`:

- `trace-origins.ts` implements the frozen `TraceOriginsV2` signature as one graph per
  canonical, scoped factual claim. It accepts only mechanically valid `validated` Task 07
  assessments, keeps unknown dependence explicit, follows explicit citation/attribution URLs,
  enforces the lower of the frozen three-hop cap and the run cap, reserves shared request
  capacity for mandatory reassessment, and emits typed partial/canceled states. Invalid IDs,
  offsets, quotes, dependence locators, snapshot collisions, archive targets, and retrieval URL
  drift are rejected rather than repaired.
- `retrieval-controller.ts` adapts Task 06's `createRetrieveEvidenceV2` controller for
  `origin_trace` follow-ups. The explicit referenced URL is a search target only; only a fully
  acquired immutable snapshot whose URL still matches is accepted. One request remains reserved
  for Task 07 assessment.
- `references.ts` extracts absolute explicit citations from immutable snapshot text with exact
  half-open UTF-16 supporting locators. `according to`, `attributed to`, `reported by`, and
  `source:` cues produce `attributes_to`; other explicit links produce `cites`. It does not infer
  an original from a slug, snippet, hostname, or model guess.
- `chronology.ts` preserves snapshot publication, update, event, index, archive, and capture
  assertions without replacing unknown intervals. It detects backdated updates,
  claim-validated archive observations before declared publication, and graph cycles. Candidate
  roots distinguish primary records, earliest observed statements within the searched scope,
  and earliest retrieved reports. Overlapping earliest intervals and simultaneous timestamps
  remain tied rather than forcing a unique root.
- `types.ts` defines injected provenance retrieval and archive lookup boundaries plus options.
  The archive port returns capture URL, original URL, and a typed observation interval; it does
  not itself make a capture claim admissible.
- `index.ts` is the `@repo/ai/core/provenance` entry point.
- `fixtures/provenance-invariants.json` freezes the seven synthetic pass-condition cases and
  states that human-gold claims are zero.

Every newly acquired traversal or archive snapshot is immediately passed through Task 07's
`AssessEvidenceV2` before `claimPresentInContent` can become true. `newSnapshotIds` still returns
those immutable IDs so Task 11's orchestrator can invalidate the evidence-set hash, persist the
new assessment result, and reassess before Task 09 adjudication. An archive URL match without a
validated claim excerpt creates document-history context only; it cannot establish claim-level
existence or an earliest-observed root.

## Contract and API examples

```ts
import {
  createProvenanceRetrievalController,
  createTraceOriginsV2,
  type ArchiveLookupPort,
} from "@repo/ai/core/provenance";

const traceOrigins = createTraceOriginsV2({
  retrieval: createProvenanceRetrievalController(retrievalOptions),
  archive,
  priorExternalRequests: retrievalAndAssessmentRequests,
  priorCostUsd: retrievalAndAssessmentCost,

const result = await traceOrigins(
  { claims, snapshots: immutableSnapshots, assessments },
  environment,
);
```

## Security, tenancy, visibility, cancellation, and audit

The stage has no database global, `process.env`, direct `fetch`, provider global, or production
fallback. Search and acquisition flow through Task 06 and the frozen environment ports; model
assessment flows through Task 07; archive discovery is an injected port. Task 03 storage and
Task 06 retrieval retain exact tenant, owner, and visibility enforcement. Public visibility does
not imply publication consent or cross-owner sharing.

Untrusted document text remains data. Traversal uses only explicit absolute URLs with exact
supporting locators. Newly returned documents must match the requested URL and validate the
scoped claim before becoming claim-level evidence. Rejected and `needs_human_review`
assessments are not promoted; unknown dependence remains explicit. Shared external-request and
cost caps are fail-closed, archive/retrieval outages and inaccessible originals remain visible,
and cancellation returns `failed` with no partial graph. Audit events record stage lifecycle,
reassessment, and cancellation using bounded messages and run/claim/snapshot identities.
