## Changed files and behavior

Owned path `packages/ai/src/core/evidence/`:

- `assess-evidence.ts` implements the frozen `AssessEvidenceV2` signature. It accepts only IDs in
  `admittedSnapshotIds`, fails closed on missing IDs, derives passage pairs from immutable snapshot
  locators (or the complete normalized text when locators are absent), and assesses every eligible
  canonical claim/passage pair. `needs_context` claims are assessed exactly as written but can never
  produce sufficient feedback. Unanswerable, non-checkable, duplicate, and deferred claims are not
  silently promoted. Cancellation, request limits, deadlines, model usage, partial provider failure,
  and audit events are explicit.
- `generation.ts` defines the strict structured relation schema and prompt. The claim and acquired
  passage are passed as JSON-labelled untrusted data. The model must return exact IDs, one verbatim
  quote, relation, four applicability dimensions, directness, and a concise justification. It never
  returns offsets, dependency groups, validation status, verdicts, confidence, or private reasoning.
- `validation.ts` mechanically derives half-open UTF-16 excerpt offsets and requires one exact quote
  occurrence inside the requested passage. It rejects invented/ambiguous quotes and mismatched claim
  or snapshot IDs. Deterministic checks cover entity, explicit year, jurisdiction/place, attribution,
  negation, units, denominator, and calculations. Failed checks produce a retained `rejected`
  assessment plus `citation_validation_failed`. Invalid IDs or quotes are excluded with typed issues
  and audit records because the frozen report contract requires every included excerpt to reproduce
  snapshot text. Uncertain applicability produces
  `needs_human_review`. Available fraction operands produce stored calculation steps and a numeric
  result.
- `dependence.ts` groups canonical duplicate content and copied normalized excerpts, detects cited
  source attribution from excerpt locators, and groups same-publisher material without treating
  separate URLs as independent. Every syndicated, citation, or same-publisher relation retains a
  supporting locator. Primary acquired records may establish an origin group; secondary and submitted
  assertions default to `unknown`. Domain diversity alone is never used to establish independence.
- `sufficiency.ts` exports Task 06 feedback with explicit independent and unknown origin counts,
  missing primary/counter/time/jurisdiction/numeric/full-document needs, and traceable suggested
  queries. A usable applicable primary record or two established independent groups is required;
  unresolved-context claims stay insufficient.
- `challenge.ts` builds a label-blind challenge input from the scoped claim and only validated,
  fully applicable assessments. Its type has no draft label or model-confidence field.
- `types.ts` and `index.ts` expose the stage factory, frozen-stage implementation, challenge builder,
  source-dependence classifier, sufficiency builder, strict generation schema, and bounded options.
- `fixtures/evidence-invariants.json` is the synthetic, hash-stable Task 07 fixture containing the
  seven pass-condition cases.

## Contract and API examples

```ts
import { buildChallengeInput, createAssessEvidenceV2 } from "@repo/ai/core/evidence";

const assess = createAssessEvidenceV2({
  maxGenerationRequests: remainingRequests,
  deadlineMonotonicMs: runDeadline,
});
const result = await assess(
  {
    claims: inventory.claims,
    snapshots: retrieval.data.snapshots,
    admittedSnapshotIds: retrieval.data.admittedSnapshotIds,
  },
  environment,
);
const challenge = buildChallengeInput(claim, result.data?.assessments ?? []);
```

An invalid generated source reference is rejected before it enters the assessment array and remains
visible through a typed issue and audit event:

```json
{
  "code": "citation_validation_failed",
  "message": "A generated assessment used an invalid ID or invented/ambiguous excerpt and was rejected.",
  "claimId": "claim_expected",
  "snapshotId": "snapshot_expected"
}
```

Ten exact syndicated copies carry one `dependencyGroupId`; nine are
`dependence: "syndicated_copy"` with exact supporting locators. Separate domains do not increase
`independentOriginCount`.

## Security, tenancy, visibility, cancellation, and audit

The stage has no database global, `process.env`, direct network call, or provider global. All model,
clock, cancellation, and audit behavior uses the frozen `RunEnvironment`. Snapshot tenancy, owner,
and visibility were already enforced by Task 03 storage and Task 06 retrieval; this stage accepts no
corpus/search port and cannot widen scope. Public visibility does not imply publication consent.

Untrusted claim/evidence text is JSON data, strict model output is parsed, and references are checked
against the exact requested immutable snapshot. Submitted assertions never become independent support.
Rejected and conflicting evidence is preserved rather than dropped. Cancellation before or during the
stage returns `failed`, no partial data, and a typed `cancellation_requested` issue. Audit events cover
start/finish, every generation request, each validation rejection, and cancellation using only run,
claim, and snapshot identities plus bounded messages.
