## Changed files and behavior

Owned path `packages/ai/src/core/retrieval/`:

- `questions.ts` creates answerable neutral, supporting, disconfirming, primary-source, and
  date-constrained questions from the frozen scoped claim fields. Attribution, negation,
  quantities and denominators, explicit time, place, and qualifiers survive query planning.
  Attributed statements get a separate exact-statement query. `needs_context` claims remain
  quoted as written; unresolved entities are never filled in. Quoting and sufficiency-suggested
  rewrites carry traceable transformation records. `retrievalText` is not used as claim identity.
- `discovery-adapters.ts` implements the frozen generic `SearchPort` candidate-generator
  adapter, stable content-derived candidate IDs, a primary-source resolver adapter, and named
  wrappers for the existing Google Fact Check, NewsAPI, GDELT, Google News, and Bing News
  discovery channels. Every result remains structurally `admissible: false`; snippets and
  provider ratings are metadata only. The adapters accept injected clients and perform no
  direct network or environment access.
- `retrieve-evidence.ts` implements the frozen `RetrieveEvidenceV2` signature. It retrieves
  only canonical `factual_claim` inventory entries; duplicates, deferred claims, opinions, and
  unanswerable claims are not silently promoted. Counterevidence runs first, and the shared
  request budget reserves both a fetch for the current claim and a counter-query plus fetch for
  each later claim. Per-claim query/fetch caps, prior-stage usage, cost ceilings, cancellation,
  and at most two targeted sufficiency rounds are enforced. `budgetUsed` lets Task 11 pass the
  remaining global allowance onward.
- Discovery, full-document acquisition/extraction, persistence, passage selection, and optional
  reranking are separate operations. Only a nonempty, untruncated, fully extracted snapshot
  whose original URL matches its candidate is stored and included in
  `admittedSnapshotIds`. That name means eligible for Task 07 assessment, not validated
  evidence. Every passage has `requiresAssessment: true`; lexical overlap only orders the
  bounded pool and never establishes entailment or admissibility. Failed or truncated fetches
  leave snippets as candidates and admit no snapshot.
- Corpus proposals are requested with exact tenant, owner, and visibility scope, and the
  response is rechecked for that scope plus content hash, proposition key, temporal scope,
  retriever version, role, and complete extraction. The port returns immutable snapshot
  references only, so earlier model verdicts/reasoning are never consumed as support. The
  submitted input URL and submitted-input corpus snapshots are rejected as independent
  corroboration.
- Every query, accepted result, rejected result, duplicate, fetch, fetch failure, omission,
  capability gap, cost value, budget exhaustion, cancellation, and stopping reason is recorded
  through the frozen audit port. Successful empty search is `complete/no_results`; absent
  search capability is `unavailable/capability_unavailable`; total search failure is
  `unavailable/provider_outage`; exhausted work is `partial/budget_exhausted`.
- `passages.ts`, `types.ts`, and `index.ts` expose the bounded passage selector, injected
  discovery/corpus/primary/reranker boundaries, and the retrieval entry point without changing
  a frozen contract.
- `fixtures/retrieval-replay.json` is the checked-in, hash-stable synthetic replay set for the
  five pass-condition cases: strong official evidence outside news, disconfirming evidence for
  a contradicted claim, historical evidence, API outage, and exhausted budget.

## Contract and API examples

```ts
import { createExistingDiscoveryAdapters, createRetrieveEvidenceV2 } from "@repo/ai/core/retrieval";

const retrieve = createRetrieveEvidenceV2({
  priorExternalRequests: extractionResult.metrics.externalRequests,
  searchPorts: createExistingDiscoveryAdapters(discoveryClients, environment.ports.clock),
  primarySourceResolver,
  corpus: tenantScopedCorpus,
  reranker,
});

const result = await retrieve(
  { claims: inventory.claims, snapshots: inputs, round: 0, sufficiency: [] },
  environment,
);
```

## Security, tenancy, visibility, cancellation, and audit

All content and provider metadata remain untrusted data. The controller makes no direct network,
database-global, `process.env`, provider-global, or model call. Document network safety remains in
Task 04's `DocumentAcquisitionPort`; immutable and scoped storage remains in Task 03's ports.
Corpus scope is passed and verified as exact tenant ID, owner ID, and visibility. Public
visibility does not imply publication consent or cross-owner sharing. The submitted document
cannot independently corroborate itself. Cancellation is checked before discovery, between
claims, and after external work; a canceled stage returns `failed` with no partial data and a
typed `cancellation_requested` issue. Audit events carry only run, claim, and snapshot identities
plus bounded operational messages.
