## Behavior/API examples

The focused policy is available from `@repo/ai/core/publication`:

```json
{
  "policyVersion": "core-v2-focused-publication-1.0.0",
  "decisionVersion": "core-v2-focused-decision-1.0.0",
  "mode": "evidence_gated",
  "scoreFormulaVersion": "focused-supported-share-1.0.0",
  "calibration": {
    "status": "not_used",
    "probability": null,
    "reason": "Focused policy is evidence-gated and does not use statistical calibration."
  }
}
```

A passed decision has `focusedPublication.status: "published"` and `gate: "passed"`, while its
compatibility `calibration` remains `applicability: "unavailable"` with a null correctness value.
For example, a weak or invalid citation is returned as:

```json
{
  "diagnosticLabel": "supported",
  "publishedLabel": "unverified",
  "reasonCodes": ["focused_evidence_gate_abstained"],
  "focusedPublication": {
    "status": "abstained",
    "gate": "invalid_citation"
  }
}
```

The focused policy stage has zero external requests, token usage, and cost. It occupies the
existing `calibrate_decisions` stage name only to preserve checkpoint and report compatibility;
focused audit messages identify it as evidence publication. The old `createCalibrateDecisionsV2`
stage remains available and still publishes decisive diagnostics as `unverified` when its required
calibration artifact is absent.
