  `normalize_input` job, leases that exact run, executes the focused runtime, persists the report,

## Behavior/API examples

New submissions use the authenticated API route:

```http
POST /api/tracera/v2/analyze
Authorization: Bearer <session>
Idempotency-Key: analysis-123
Content-Type: application/json

{"text":"The article says ..."}
```

The same route accepts a public article link or image:

```json
{ "url": "https://example.test/public-article" }
```

```json
{ "image": "data:image/png;base64,...", "imageMimeType": "image/png" }
```

A completed or partial run returns the persisted focused report and control URLs:

```json
{
  "schemaVersion": 2,
  "status": "complete",
  "runId": "run-123",
  "report": { "schemaVersion": 2, "status": "complete" },
  "progressUrl": "/api/tracera/v2/runs/run-123",
  "eventsUrl": "/api/tracera/v2/runs/run-123/events",
  "cancelUrl": "/api/tracera/v2/runs/run-123/cancel",
  "reportUrl": "/api/tracera/v2/runs/run-123/report"
}
```

If deployed configuration is missing, fixture mode is requested outside tests, or the run cannot
be completed safely, the response remains explicit rather than silently falling back:

```json
{
  "schemaVersion": 2,
  "status": "unavailable",
  "code": "core_v2_unavailable",
  "error": "Core v2 Focused is unavailable until ... is explicitly configured."
}
```

Provider failure, timeout, and budget exhaustion use a saved failed or unavailable report with
an explicit `provider_failure`, `timeout`, or `budget_exhausted` unresolved reason when the run
has reached terminal report persistence. An idempotent repeat returns the original `runId` and
replay response instead of executing a second analysis. Run and evidence reads remain scoped to
the authenticated owner/tenant. Existing saved v1 reports still decode and render through the
legacy report projector; new submissions do not use the legacy analysis endpoints.

## Limitations and successor instructions

- Deployed focused analysis requires explicit `TRACERA_ANALYSIS_MODE=live`, supported provider
  credentials, model and embedding settings, all `CORE_V2_MAX_*` bounds, and positive AI daily
  spend/estimate controls. Missing configuration returns an explicit unavailable result. Do not
  infer a provider, model, credential, budget, or deployment setting.
- The default request executor is live-only. Fixture behavior is limited to injected tests and
  is not a production fallback. The execution path is intentionally one bounded on-demand run in
  the existing web/API process; no worker dependency was introduced.
- Public Google News RSS and GDELT discovery have no billable provider cost in this adapter and
  are not presented as provider usage measurements. Credentialed discovery costs remain unknown
  unless configured, and unknown costs fail closed under the run cap. Configured AI estimates are
  safety controls, not measured billing or quality metrics.
- The local profile remains unavailable for the focused user route unless the explicit deployed
  live policy is satisfied; existing local v1 fixture behavior is retained only for compatibility
  and historical flows. The offline e2e check therefore requires its provisioned database engine.
- The deterministic API/fixture coverage is an engineering regression guardrail only. It is not a
  human-gold research program, calibration evidence, statistical release gate, provider
  measurement, or proof of population-level accuracy. Do not describe the focused product as
  statistically calibrated or universally accurate.
- Preserve immutable input/evidence snapshots, exact quote and offset validation, source
  applicability and independence checks, temporal/entity/jurisdiction checks, safe-fetch and
  prompt-injection protections, auth/tenant/visibility isolation, idempotency, quotas, spend
  limits, cancellation, explicit partial/unavailable/unknown states, and v1 decoding when
  extending this boundary. Any future deployment exercise must be separately authorized.
