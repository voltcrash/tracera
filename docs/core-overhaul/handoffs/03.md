## Storage and API behavior

`CoreStorageRepository` is constructed with a query/transaction pool. Every operation
requires the exact `{tenantId, ownerUserId, visibility}` scope. A public snapshot is not
shared across owners or tenants because `RunContext` contains no publication-consent
proof; a future sharing path must add an independently authorized publication-policy
input rather than infer consent from `visibility`.

```ts
const repository = new CoreStorageRepository(pool);
const snapshots = createSnapshotStore({ repository, context, blobStore });
const runs = createRunStore({ repository, context });
```

`checkpoint` validates both the explicit attempt and fencing token against an unexpired
lease. The frozen `RunStorePort.finalize` signature contains a fencing token but no
attempt field; finalization resolves the current attempt under a row lock from that
unique token, then uses both attempt and token in the completion update. An expired or
superseded worker therefore cannot checkpoint, retry, renew, cancel, or finalize.

Duplicate enqueue is idempotent only when the run identity, payload, and retry policy
match. Reusing a key with different immutable input, engine/budget identity, payload, or
retry policy fails with `CoreStorageConflictError`.

Snapshots are insert-only within an ownership scope. Reusing a snapshot ID requires
JSON equality and the same content hash. Embedding reuse additionally requires the exact
model, dimensions, preprocessing, and vector; dimensions remain 1024. Stored blobs need
a locator, a `rawContentHash`, and a `RawBlobStore`; unavailable blobs keep a null
locator. The raw hash on a stored locator is checked against resolved bytes before
persistence. `RawBlobStore.put` returns the same explicit stored/unavailable union for
Task 04 acquisition.

Finalization parses the complete v2 report and writes the report version, snapshot
references, claims, assessments, provenance edges, decisions, diagnostic labels,
published labels, nullable factual score, and complete null-reason array in one
transaction before fenced job completion. It never reconstructs a score from counts.
Replay reads return a schema-validated exact version or the latest version within the
same ownership scope.

Report-snapshot references use `ON DELETE RESTRICT`; snapshots referenced by a report
must be retained for the life of that report. Unreferenced embeddings cascade when an
unreferenced snapshot is deleted. This task adds no deletion job or retention duration,
so it cannot accidentally delete report evidence.
