## Changed files and behavior

Owned path `packages/ai/src/core/adjudication/`:

- `adjudicate-claims.ts` implements the frozen `AdjudicateClaimsV2` signature through
  `createAdjudicateClaimsV2(options)`. It emits one decision per canonical `factual_claim`
  (duplicates, deferred, and non-factual dispositions receive none, so Task 10 can count them as
  omitted/deferred). Per claim, in order:
  1. `needs_context`/unresolved context, `unanswerable`, and `not_checkable` claims abstain as
     `unverified` with exact reason codes before any evidence read or model call.
  2. A provenance graph node with `claimPresentInContent: true` whose snapshot has no supplied
     assessment for the claim means Task 08 evidence was never reassessed; the claim abstains with
     `awaiting_deferred_processing` rather than adjudicating stale assessments.
  3. Immutable snapshots are read only through the frozen `SnapshotStorePort`. Every assessment for
     the claim is re-verified mechanically (frozen schema, snapshot present, excerpt and dependence
     locator offsets reproduce their quotes, validated assessments carry a passing
     `quote_offsets` check). Any failure yields `unverified`, `citationIntegrity: "invalid"`, and
     `citation_validation_failed` without calling a model.
  4. Usable evidence is `validated`, fully applicable, `supports`/`contradicts`/`context`, and not
     from a `submitted_input` snapshot. Rejected checks and `not_applicable` dimensions contribute
     `evidence_not_applicable_in_time|to_entity|in_jurisdiction`; `needs_human_review` is surfaced
     as an issue and never used. With no usable support or contradiction the claim abstains
     deterministically with `no_admissible_evidence` plus those exclusion reasons and **zero**
     model calls.
  5. Otherwise a structured draft is requested through `GenerationPort`. The draft cannot choose
     reason codes; they are derived deterministically. `resolveDraft` rejects (never repairs)
     unknown/unusable IDs, duplicate citations, wrong relation roles, or label/role mismatches.
     `supported`/`contradicted` require a usable independent primary record or two independent
     origin groups on the cited side (`insufficient_independent_origins` otherwise);
     `misleading` requires cited stated-assertion support plus independently sourced corrective
     `context`; `mixed` requires a material claim and both sides.
  6. Every decisive draft is challenged by a separate `GenerationPort` request built from Task 07's
     `buildChallengeInput`: only the claim and usable evidence, never the draft label,
     justification, or self-confidence. Invalid challenge output marks the challenge `failed`.
  7. Challenger disagreement, or any applicable opposing evidence, triggers exactly one targeted
     round (if configured, within `maxTargetedRetrievalRounds` and the shared request/cost caps):
     Task 06 retrieval with forced disconfirming/primary-source feedback, Task 07 assessment of
     newly admitted snapshots, a required `record` callback, then one more label-blind challenge.
     A decisive verdict is resolved only when the challenger agrees and opposing evidence is
     absent (or, after the round, still lacks independent origins). Otherwise the conflict is
     persisted without voting: both sides sufficient on a material claim become `mixed`
     (`unresolved_material_conflict`); anything else keeps the draft as the diagnostic label with
     `unresolved_challenge_disagreement`/`unresolved_material_conflict` and a non-decisive
     published label. Missing capability is an explicit `capability_unavailable` issue.
  8. Adjudication never publishes a decisive label: decisive diagnostics leave this stage as
     `publishedLabel: "unverified"` with pending `calibration: unavailable` and
     `calibration_unavailable`. `rawModelConfidence` stores the draft's uncalibrated self-score.
     Provider failures omit the claim with a `provider_failure` issue (partial stage) instead of
     guessing. Budget exhaustion abstains with `budget_exhausted_before_resolution`. Cancellation
     returns `failed`, no data, `cancellation_requested`, and a cancellation audit event.
- `policy.ts` holds the deterministic, replayable policy (scope abstention, integrity, partition,
  origin sufficiency, draft and challenge validation).
- `generation.ts` defines strict draft/challenge output schemas and prompts
  (`core-v2-adjudication-1.0.0`, `core-v2-challenge-1.0.0`). Untrusted claim/evidence travel only
  as JSON data; outputs contain no private reasoning.
- `types.ts`, `index.ts` (`@repo/ai/core/adjudication`), and
  `fixtures/adjudication-invariants.json` (7 synthetic cases, 0 human gold).

Owned path `packages/ai/src/core/calibration/`:

- `features.ts` extracts the versioned PLAN.md feature vector
  (`core-v2-calibration-features-1.0.0`): label indicators, cited count, independent/unknown
  dependency groups, primary-directness share, all scope checks passing, opposing applicable
  assessments, challenge agreement, targeted rounds, and the model self-score with a presence flag.
- `logistic.ts` is a deterministic Newton-Raphson L2-regularized logistic regression on
  standardized features.
- `artifact.ts` defines the frozen calibrator artifact (model, per-language/label slices with
  thresholds, dataset/observation hashes, `split: "calibration"`, grouped out-of-fold fit record,
  validity window, and a SHA-256 content hash). `checkCalibratorArtifact` returns `unavailable`
  for no artifact and `invalidated` for schema failure, hash tampering, a run that does not pin
  this `versions.calibration`, stale engine/prompt/model/retriever, changed feature/evidence/
  adjudication/challenge prompt versions, expiry, a fit time after the run clock, or a
  `synthetic_fixture` artifact outside `executionMode: "fixture"`.
- `calibrate-decisions.ts` implements the frozen `CalibrateDecisionsV2` signature through
  `createCalibrateDecisionsV2({ artifact })`. Missing/invalidated artifacts, out-of-slice
  decisions (including unknown language), and feature/citation failures give
  `calibratedCorrectness: null` and an `unverified` published label while preserving
  `diagnosticLabel`, cited IDs, challenge, and `rawModelConfidence`. An in-slice decision gets the
  logistic probability; it is published decisively only when the probability meets the slice's
  frozen threshold, the challenge is `resolved`, and citations still resolve to validated
  assessments of the claim. `mixed`/`unverified` diagnostics publish unchanged. Every decision is
  re-parsed through the frozen `decisionSchema`. Gating writes `decision_gated` audit events.
- `fit.ts` implements `fitCorrectnessCalibrator` and `evaluateCorrectnessCalibrator` over the Task
  01 dataset schema. Both validate dataset schema/hash, observation-set identity/hash and
  compatibility versions, duplicate or unknown claims, and Task 01 split leakage
  (`validateSplitLeakage`). Fitting **refuses** any observation outside the calibration
  partition, uses only `adjudicated_human` labels under `RELEASE_CALIBRATION_POLICY`
  (500 decisive observations, 50 per slice, 0.95 precision target), computes out-of-fold
  predictions grouped by `eventGroupId`, selects per slice the smallest threshold whose one-sided
  Wilson lower bound (Task 01 `wilsonLowerBound`, z=1.6448536269514722) meets the target, and
  reports out-of-fold ECE/Brier/bins through Task 01's `evaluateRun`. Too little human gold or too
  few event groups returns `blocked` and writes no artifact. Evaluation accepts only
  development/temporal partitions, or `test` behind an explicit sealed-release flag.
- `fixtures/synthetic-observations.json` is a one-observation synthetic set over the Task 01
  invariant dataset used to demonstrate the blocked CLI path.
- `index.ts` is `@repo/ai/core/calibration`.

## Security, tenancy, visibility, cancellation, and audit

Both stages use only `RunEnvironment` ports: no database global, `process.env`, `fetch`, or
provider global. Snapshots come from the scoped `SnapshotStorePort`, so Task 03 tenant, owner, and
visibility enforcement is preserved; public visibility is not treated as publication consent.
Targeted retrieval reuses Task 06's scoped controller and Task 07 assessment. Untrusted text is JSON
data; model output is schema-parsed and mechanically validated. The submitted document cannot
corroborate itself; model votes are not evidence and are never counted. Raw model confidence is
never a calibrated probability. Cancellation is checked before each claim and around every external
call. Audit events cover start/finish, each generation or targeted request, rejected output,
decision gating, and cancellation, with only run and claim identities plus bounded messages.
